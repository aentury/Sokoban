# Sokoban 推箱子

一个用 Unity 制作的推箱子游戏，包含完整的关卡流程和游戏内关卡编辑器。

## 运行

- 引擎版本：**Unity 2022.3.51f1**（2D，Built-in Render Pipeline）
- 用 Unity Hub 打开项目根目录，打开场景 `Assets/Scenes/Main.unity`，点击 Play
- 界面语言：简体中文
- 没有使用任何第三方插件或额外的 Package

## 操作

| 场景 | 按键 |
|---|---|
| 游玩 | 方向键 / WASD 移动（按住连续行走），Z 撤销，R 重开，Esc 暂停 |
| 通关面板 | Enter / Space 进入下一关 |
| 关卡编辑器 | 左键绘制，右键擦除，1–5 切换工具，Z 撤销，Esc 返回 |

## 功能

**游戏流程**
- 主菜单 → 选关 → 游玩 → 暂停 / 通关结算 → 下一关
- 12 个内置关卡，由浅入深（1 个箱子到 4 个箱子），全部经过求解器验证可解
- 通关解锁下一关，记录每关最佳步数，存档保存在本地（重启后保留）
- 无限撤销、重开、步数和推箱次数统计
- 设置：总音量

**手感**
- 移动补间动画；动画期间的输入会缓存一步，不丢键、不错位
- 撤销 / 重开时画面直接对齐到逻辑状态
- 撞墙时角色轻微顶一下并有音效；箱子推上目标点有提示音，通关有庆祝动画
- 界面切换淡入；相机根据关卡大小和窗口比例自动适配；UI 按 1920×1080 参考分辨率缩放

**关卡编辑器（游戏内）**
- 画笔工具：墙、箱子、目标点、玩家、橡皮擦，支持拖动连续绘制
- 调整关卡尺寸（3×3 到 20×14）、新建、撤销（每一笔为一步）
- 合法性校验：必须有且只有一个玩家；箱子数等于目标数且至少一个；玩家所在区域必须被墙封闭；箱子和目标都要在玩家能到达的区域内
- **检查是否有解**：在后台线程运行求解器，判断关卡是否有解，并给出最少推箱次数
- **试玩**：直接试玩当前关卡，通关或按 Esc 回到编辑器，编辑内容不会丢失
- 保存 / 编辑 / 删除自制关卡，在选关界面的「我的关卡」分页中游玩

## 架构

```
Assets/_Project/
  Scripts/Core/       Sokoban.Core —— 纯 C# 逻辑层，不引用 UnityEngine
    Board               棋盘状态、移动、推箱、撤销、重开、胜利判定
    LevelParser         XSB 文本 ⇄ Board
    LevelPackParser     多关卡文本文件的切分
    LevelGrid           编辑器中的网格与画笔规则
    LevelValidator      关卡合法性检查
    Solver              按推箱次数的广度优先搜索求解器
    SaveData            存档规则（新纪录、解锁）
  Scripts/Game/       Sokoban.Game —— Unity 表现层
    App                 入口与界面状态机
    GameController      输入处理、驱动 BoardView、通关判定
    BoardView           棋盘渲染与动画
    LevelEditor/        编辑器控制器、网格视图、编辑器界面
    UI/                 UIFactory（统一风格的控件）与各个界面
    SaveSystem, CustomLevelStore, LevelLibrary, Sfx, SpriteLibrary
  Tests/EditMode/     针对 Core 的单元测试
  Resources/          关卡、贴图、音效、字体
```

**设计要点**

- **逻辑与表现分离**：所有规则都在 `Sokoban.Core` 中，程序集设置了 `noEngineReferences`，由编译器保证逻辑层不依赖 Unity。规则因此可以直接做单元测试，表现层也可以随意替换。
- **逻辑先行，画面追赶**：按键时逻辑立刻生效，`BoardView` 只负责把物体动画到逻辑位置。撤销、重开时画面直接对齐，从根本上避免画面与逻辑错位。
- **撤销**：每一步移动返回一个 `MoveResult`，它既是表现层播放动画的依据，也是压入撤销栈的记录。
- **数据驱动的关卡**：使用通用的 XSB 文本格式（`#` 墙、`@` 玩家、`$` 箱子、`.` 目标、`*` 箱子在目标上、`+` 玩家在目标上），可以直接导入现成的关卡包。
- **求解器**：状态 = 箱子位置 + 玩家所在的连通区域，并剪掉"箱子被推进非目标死角"的分支。状态数有上限，在后台线程运行，不会卡住界面。

## 取舍与说明

- **UI 由代码生成**：所有界面在运行时由 `UIFactory` 搭建，场景里只有一个 App 物体。风格统一、不依赖手动拖拽的引用；代价是在编辑器的 Hierarchy 里看不到预先摆好的 UI。
- **单场景 + 状态机**：界面之间切换不需要加载场景，状态集中在 `App` 中，便于追踪。
- **输入**：使用 Unity 自带的 Input Manager，不额外引入 Input System 包。
- **中文字体随项目附带**：使用思源黑体（Noto Sans CJK SC）的常用字子集（约 7800 字），不依赖玩家电脑上安装的字体。
